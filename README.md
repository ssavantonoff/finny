# Finny

Finny — offline-first Flutter-приложение для Android, созданное CodexTeam для
хакатона «Лидеры цифровой трансформации 2026». Дети 7–11 лет учатся принимать
финансовые решения, заботясь о виртуальном питомце. В игре используются только
игровые монеты: регистрация, сервер и интернет для основного сценария не нужны.

## Текущее состояние

Реализованы пятидневная Campaign, Finale и продолжение в Free Play. Игрок
планирует траты по направлениям «Нужно», «Хочу», «Копилка», сравнивает План и
Факт, выполняет шесть финансовых заданий, покупает вещи и копит на одну из трёх
целей. Финни растёт в три этапа; внешность выбирается из трёх цветов и трёх
узоров — всего 27 комбинаций готовых изображений.

Home показывает Финни, баланс, состояние, цель и действия дня. Есть магазин,
«Вещи» с инвентарём, игрушечные мини-игры, аксессуары, награды для комнаты и
Finny Catch в Free Play. В Settings доступны «Как играть», «Финансовые
термины», «Прогресс» и «Для взрослого». Состояние хранится локально в SQLite.

## Путь игрока

```text
Onboarding → создание Финни → День 1 → День 2 → День 3 → День 4 → День 5
           → итоги / рост → Finale → Free Play
```

Профиль создаётся локально, без регистрации. Игрок выбирает имя профиля, затем
имя и внешность Финни. Игровые дни идут последовательно по действиям игрока:
ожидать наступления реальных суток не нужно. После пятого дня нет Day 6.
Завершение периода показывает План/Факт; после дней 2 и 5 есть отдельный экран
роста. Финал предлагает сразу продолжить с Финни либо вернуться к этому решению
позже через экран завершённой Campaign.

## Бюджет и задания

В начале периода можно менять черновик бюджета. При подтверждении суммы для
«Нужно», «Хочу» и «Копилка» проверяются по правилам игры; подтверждённый план
сохраняется для сравнения с фактическими операциями. Остаток кошелька переходит
в следующий день отдельно от накоплений. Игровые ошибки в заданиях можно
исправлять: они сопровождаются объяснением и не отнимают уже полученный прогресс.

Шесть заданий из [`assets/content/tasks.json`](assets/content/tasks.json):

| День | Название в игре | Механика |
| --- | --- | --- |
| 1 | «Нужно или хочу?» | Распределение покупок по категориям |
| 2 | «Что важнее сейчас?» | Приоритеты в условном бюджете 150 монет |
| 3 | «Планы изменились» | Изменение условного плана после потери 80 монет |
| 4 | «Покупки с умом» | Выбор упаковок и количества в рамках бюджета |
| 5 | «Собери свой бюджет» | Самостоятельный выбор покупок и суммы на цель |
| 5 | «План изменился» | Пересмотр плана после неожиданной траты |

Оба задания дня 5 выполняются независимо. Условные расходы учебных заданий не
являются покупками в магазине; награды начисляются через игровые правила.

## Магазин, вещи и копилка

Магазин показывает категорию, цену и назначение вещи и запрашивает
подтверждение покупки. При нехватке монет покупка не проходит. Купленные вещи
сохраняются в «Вещах»; использование еды и ухода отделено от покупки.
Приобретённые игрушки открывают взаимодействия с мячом, фрисби и машинкой.
В Free Play на Home доступна также мини-игра Finny Catch.

Аксессуары — **Кепка**, **Бандана** и **Крылья**. Они экипируются в разные слоты,
поэтому могут отображаться на Финни одновременно. Три цели копилки — «Ночник
для Финни» (400), «Самокат для Финни» (600) и «Игровой домик для Финни» (900)
монет. Выбранная цель показывает накопленную сумму и остаток; после достижения
цель можно подтвердить и получить награду для комнаты. Home отображает
полученные награды, включая их сочетания.

## Подсказки и прогресс

«Как играть» повторяет определения из onboarding: «Нужно» — то, без чего
Финни трудно обойтись; «Хочу» — приятные покупки, которые можно отложить;
«Копилка» — монеты для будущей цели. «Финансовые термины» — короткий словарь.
Постоянный экран «Прогресс» показывает текущую цель, завершённые финансовые
задания и План/Факт **последнего** завершённого периода. Он отличается от
временного экрана роста Финни после дней 2 и 5.

## Демонстрация и локальные данные

Демонстрационный режим Finny не является отдельным экраном. Campaign устроена
так, что все пять игровых дней можно пройти за одну сессию без календарного
ожидания. Для экспертной проверки используется обычный локальный тестовый
профиль. В «Настройки → Для взрослого» после удержания кнопки можно:

- «Сбросить игровой прогресс», сохранив имя профиля и внешность Финни;
- «Удалить локальный профиль», чтобы повторить полностью чистый первый запуск.

Оба действия требуют подтверждения. В архитектуре есть техническая поддержка
профиля типа DEMO, но обычный запуск приложения создаёт профиль NORMAL и не
предлагает пользователю отдельный DEMO UI. Подробный маршрут — в
[сценарии демонстрации](docs/DEMO_SCRIPT.md).

SQLite (текущая schema version **14**) сохраняет профиль, питомца, кошелёк,
периоды и бюджет, транзакции, задания, накопления и завершённые цели,
инвентарь, экипировку, состояние Campaign и Free Play. Повторный запуск
восстанавливает локальный прогресс.

## Разработка

Архитектура: UI → Riverpod controllers → domain services → repositories →
SQLite / JSON content. Канонические цены, награды и эффекты берутся из content
и Core; UI не изменяет кошелёк или прогресс напрямую. Подробнее — в
[архитектуре](docs/ARCHITECTURE.md) и [Core Game Loop](docs/CORE_GAME_LOOP.md).

Нужны Flutter SDK и настроенный Android toolchain:

```bash
flutter pub get
flutter run
```

Перед review:

```bash
dart format --output=none --set-exit-if-changed .
flutter analyze --no-pub
flutter test --no-pub --concurrency=1
git diff --check
```

## Android release

`applicationId` — `ru.codexteam.finny`; версия из `pubspec.yaml` — `1.0.0+1`.
`minSdk`, `compileSdk` и `targetSdk` берутся из установленного Flutter SDK;
точные значения итогового APK проверяются при release. Для release-подписи
нужен постоянный keystore вне репозитория и локальный `android/key.properties`
с `storeFile` (абсолютный путь), `storePassword`, `keyAlias`, `keyPassword`.
Ключ и пароли не добавляются в Git. Если файл, значения или keystore не готовы,
release-сборка завершается ошибкой; fallback на debug-подпись отсутствует.

```bash
flutter build apk --release
apksigner verify --verbose --print-certs build/app/outputs/flutter-apk/app-release.apk
```

Проверка сертификата, чистая установка, физическое устройство, доступность и
материалы публикации требуют отдельной release-проверки. Их статус отражён в
[матрице требований](docs/REQUIREMENTS_MATRIX.md).
