# Finny — shotlist для screenshots

Этот список описывает, какие состояния нужно снять для презентации, submission и
README. Он не создаёт screenshots и не подтверждает, что внешний artifact уже
существует. Статус в колонке `Когда снимать` означает готовность состояния:

- **Можно сейчас** — экран и состояние уже доступны в текущем `main` при
  подготовленном NORMAL-профиле.
- **После UI polish** — базовая функция есть, но перед публичным кадром нужен
  согласованный визуальный polish.
- **После product fix** — текущий сценарий или данные ещё не закрывают нужный
  кадр; сначала требуется отдельное product решение/изменение.
- **После final/device QA** — кадр нужно перепроверить на целевом Android-
  устройстве и финальной сборке.

Каждый screenshot должен быть сделан без личных данных ребёнка, токенов,
отладочных панелей и системных уведомлений. В имени файла желательно указывать
`finny-<screen>-<state>-<date>`, а исходный PNG хранить рядом с заметкой о
версии приложения и размере viewport.

### Hero screenshots для презентации

Минимальный hero-набор — четыре кадра, которые должны читаться без устного
пояснения:

1. **Home** — Finny, три показателя и checkpoint-ы.
2. **Day 2** — бюджет 150, три покупки и зоны приоритета.
3. **Savings** — цель, progress и `Осталось`.
4. **Period Summary** — plan/fact в одной таблице.

Если нужен пятый кадр, добавить Adult overview. Reset/delete dialog использовать
только как supporting visual: не показывать на hero-кадре действие, которое
может быть воспринято как выполненное.

### Minimum screenshots для submission / RuStore

Минимальный пакет для внешней сдачи должен быть подтверждён капитаном и
финальной/device QA:

- один читаемый Home;
- один кадр ключевого задания (Day 1 или Day 2, выбор фиксируется капитаном);
- один Savings или Budget;
- один Adult overview или Period Summary;
- device screenshot с portrait/layout smoke, если он требуется конкретным
  submission package;
- отдельные store assets и 512×512 icon только в составе Final/RuStore, а не как
  автоматические Interim blockers.

Этот список не заменяет требования магазина и не подтверждает, что package уже
загружен в RuStore.

## Правила отбора и хранения

- Не снимать полный onboarding replay, повторную customization или отдельный
  DEMO reset/reseed как обязательные кадры: в текущем `main` это не подтверждено
  официальным requirement.
- Не использовать screenshot из debug-only состояния как доказательство release
  package.
- Не ретушировать ошибки, пустые значения и clipping так, чтобы кадр создавал
  ложное впечатление о текущем продукте.
- После final/device QA повторно проверить размер шрифта, нижнюю навигацию,
  overflow budget/task cards и закрытие destructive dialogs.
- Любой кадр со статусом `После product fix` остаётся вопросом продукта до тех
  пор, пока изменение не появится в main и не будет проверено.
